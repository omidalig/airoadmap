# نقشهٔ راه متن‌باز یادگیری AI و مهندسی داده

این پروژه یک نقشهٔ راه آموزشی فارسی و متن‌باز برای یادگیری مهارت‌های هوش مصنوعی و مهندسی داده است. هر مسیر بر اساس یک جایگاه شغلی واقعی طراحی شده تا یادگیرنده بداند از کجا شروع کند، چه موضوع‌هایی را با چه ترتیبی یاد بگیرد و در پایان باید توانایی انجام چه کارهایی را داشته باشد.

این نقشهٔ راه یک محتوای بسته و نهایی نیست؛ با مشارکت جامعه رشد می‌کند. توسعه‌دهندگان، متخصصان داده، مدرس‌ها و یادگیرنده‌ها می‌توانند مسیرهای موجود را اصلاح و به‌روز کنند، منابع آموزشی بهتر پیشنهاد دهند یا مسیر شغلی تازه‌ای به پروژه اضافه کنند. هدف این است که با کمک مشارکت‌کنندگان، یک مرجع آزاد، کاربردی و همیشه‌به‌روز برای یادگیری AI و مهندسی داده بسازیم.

## شروع سریع

در ویندوز روی `run-roadmap.cmd` دوبار کلیک کنید. یک سرور سبک Node.js روی پورت آزاد اجرا می‌شود و صفحه به‌صورت خودکار در مرورگر پیش‌فرض باز می‌شود. هیچ پکیج npm لازم نیست.

تا وقتی پنجرهٔ سرور باز است، اطلس کار می‌کند. برای توقف آن `Ctrl+C` را بزنید.

> `index.html` را مستقیم با `file://` باز نکنید. مرورگر در این حالت اجازه نمی‌دهد فایل‌های JSON کنار صفحه خوانده شوند.

## نقشهٔ فایل‌ها

```text
airoadmap/
├── index.html                 رابط و منطق نمایش
├── run-roadmap.cmd            اجرای آسان در ویندوز
├── server.js                  وب‌سرور سبک و بدون وابستگی
├── validate-roadmaps.js       بررسی صحت مسیرها
└── careers/
    ├── manifest.json          فهرست مسیرهای قابل نمایش
    ├── _template/
    │   └── roadmap.json       الگوی ساخت یک مسیر جدید
    ├── developer/
    │   └── roadmap.json
    ├── tester/
    │   └── roadmap.json
    └── ...
```

هر پوشه داخل `careers` نمایندهٔ یک جایگاه شغلی است و فایل `roadmap.json` تمام محتوای همان مسیر را نگه می‌دارد.

## ویرایش یک مسیر موجود

مثلاً برای تغییر مسیر توسعه‌دهنده، فایل زیر را باز کنید:

```text
careers/developer/roadmap.json
```

مراحل پیشنهادی:

1. مقدار موردنظر را در JSON تغییر دهید.
2. فایل را ذخیره کنید.
3. اگر سرور باز است، صفحه را Refresh کنید؛ کش داده‌ها غیرفعال است و تغییر بلافاصله دیده می‌شود.
4. در ترمینال دستور زیر را اجرا کنید تا خطاهای ساختاری پیدا شوند:

```powershell
node validate-roadmaps.js
```

در JSON به این نکات دقت کنید:

- رشته‌ها باید داخل `"` باشند.
- بین اعضا `,` لازم است، اما بعد از آخرین عضو نباید ویرگول بگذارید.
- شناسه‌ها مثل `role.id`، `track.id` و `chapter.id` باید انگلیسی، ثابت و یکتا باشند.
- آدرس منابع آموزشی باید کامل و با `https://` شروع شود.
- فیلد `duration` در ساختار این پروژه استفاده نمی‌شود.

## هر بخش از roadmap.json چه کاری می‌کند؟

| کلید | کاربرد |
|---|---|
| `schemaVersion` | نسخهٔ قرارداد داده؛ فعلاً همیشه `1` |
| `role` | شناسه، عنوان کامل و عنوان کوتاه جایگاه در فیلترها |
| `reviewedAt` | تاریخ آخرین بازبینی محتوای مسیر |
| `careerVideoReviewedAt` | تاریخ بررسی ویدیوی آیندهٔ شغلی |
| `guide` | معرفی شغل، آیندهٔ آن، مثال واقعی و نتیجهٔ نهایی مسیر |
| `flow` | جایگاه نقش در مراحل واقعی کار؛ هر مرحله `lead` یا `partner` است |
| `careerVideo` | ویدیوی پیشنهادی دربارهٔ آیندهٔ همان شغل |
| `phases` | سه مرحلهٔ اصلی نمایش مسیر: فهم، ساخت و اعتماد |
| `tracks` | بخش‌های قدم‌به‌قدم مسیر و موضوع‌های داخل هر بخش |
| `chapters` | فصل‌های قابل نمایش در کاتالوگ و پنجرهٔ جزئیات |
| `videos` | ویدیوی پیشنهادی فصل‌ها؛ اتصال با `chapterId` انجام می‌شود |
| `sources` | فهرست تجمیعی منابع بیرونی این مسیر |

### سطح‌ها

در `tracks[].level` از این مقدارها استفاده کنید:

- `beginner`: مبتدی
- `intermediate`: متوسط
- `professional`: حرفه‌ای

در `chapters[].level` مقدار متناظر عددی است: `1`، `2` یا `3`.

### مسئولیت در نمودار شغلی

در `flow.steps[].mode` فقط یکی از این دو مقدار را قرار دهید:

- `lead`: مسئول مستقیم اجرای مرحله و پاسخ‌گوی خروجی نهایی
- `partner`: همکار در تصمیم‌گیری، بررسی یا کنترل نتیجه

### ارتباط داده‌ها با شناسه‌ها

شناسه‌ها اتصال بخش‌های مختلف را می‌سازند:

```text
role.id ───────► roles[] در Track و Chapter
chapter.id ────► videos[].chapterId
phase.id ──────► tracks[].phase
manifest.id ───► role.id داخل همان فایل
```

اگر این شناسه‌ها دقیقاً یکسان نباشند، بخشی از مسیر در فیلتر یا صفحهٔ جزئیات ظاهر نمی‌شود.

## اضافه‌کردن یک جایگاه شغلی جدید

فرض کنیم می‌خواهیم مسیر `Product Manager` را اضافه کنیم.

### ۱. ساخت پوشه از روی الگو

پوشهٔ `_template` را کپی و با یک نام انگلیسی کوتاه تغییر نام دهید:

```text
careers/product-manager/roadmap.json
```

پوشهٔ `_template` فقط نمونه است و چون در manifest ثبت نشده، در صفحه نمایش داده نمی‌شود.

### ۲. تعیین شناسهٔ واحد

در فایل جدید این سه بخش باید دقیقاً از یک شناسه استفاده کنند:

```json
{
  "role": {
    "id": "product-manager",
    "label": "مدیر محصول AI",
    "short": "مدیر محصول"
  }
}
```

در همهٔ Trackها و Chapterهای اختصاصی همان مقدار را قرار دهید:

```json
"roles": ["product-manager"]
```

### ۳. تکمیل محتوای مسیر

در فایل الگو این قسمت‌ها را جایگزین کنید:

- معرفی شغل و خروجی نهایی در `guide`
- مراحل مسئولیت واقعی در `flow.steps`
- ویدیوی آیندهٔ شغلی در `careerVideo`
- ترتیب یادگیری در `tracks`
- فصل‌های اختصاصی در `chapters`
- ویدیوها و منابع آنلاین در `videos` و `sources`

می‌توانید فصل‌ها و Trackهای عمومی را هم در فایل جدید نگه دارید. هنگام بارگذاری، داده‌های همهٔ مسیرها بر اساس `id` ادغام می‌شوند و موارد تکراری دوباره نمایش داده نمی‌شوند.

### ۴. ثبت مسیر در manifest

فایل `careers/manifest.json` را باز کنید و جایگاه جدید را به آرایهٔ `careers` اضافه کنید:

```json
{
  "id": "product-manager",
  "file": "careers/product-manager/roadmap.json"
}
```

ترتیب آیتم‌ها در manifest همان ترتیب نمایش جایگاه‌ها در نوار فیلتر است.

### ۵. اعتبارسنجی و مشاهده

```powershell
node validate-roadmaps.js
```

اگر پیام `مسیر شغلی معتبر است` نمایش داده شد، `run-roadmap.cmd` را اجرا یا صفحهٔ باز را Refresh کنید.

## افزودن فصل جدید

برای افزودن فصل، یک شیء جدید به `chapters` اضافه کنید. حداقل موارد مهم:

```json
{
  "id": "product-discovery-with-ai",
  "order": 40,
  "sectionId": "foundation",
  "sectionTitle": "پایه‌های مدیریت محصول AI",
  "title": "کشف مسئله با کمک AI",
  "summary": "از سیگنال‌های کاربر به مسئله‌ای قابل آزمایش برس.",
  "level": 1,
  "roles": ["product-manager"],
  "roleLabels": ["مدیر محصول AI"],
  "why": "ساخت قابلیت AI بدون مسئلهٔ روشن معمولاً به یک Demo بدون ارزش تبدیل می‌شود.",
  "learningObjectives": ["تعریف مسئله", "طراحی فرضیه قابل سنجش"],
  "practice": "برای یک مسئله واقعی، Problem Statement و معیار موفقیت بنویس.",
  "subtopics": ["Problem Discovery", "Hypothesis", "Success Metric"],
  "resources": [
    {
      "title": "منبع آموزشی معتبر",
      "url": "https://example.com/learning-resource"
    }
  ]
}
```

اگر برای فصل ویدیو دارید، یک آیتم با همان شناسه به `videos` اضافه کنید:

```json
{
  "chapterId": "product-discovery-with-ai",
  "videoId": "youtube-video-id",
  "title": "عنوان ویدیو",
  "publisher": "نام ناشر",
  "publishedLabel": "زمان انتشار",
  "popularityLabel": "دلیل انتخاب",
  "sourceUrl": "https://www.youtube.com/watch?v=youtube-video-id"
}
```

## رفع خطاهای رایج

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| پیام «اطلاعات مسیرها بارگذاری نشد» | JSON نامعتبر یا مسیر اشتباه در manifest | `node validate-roadmaps.js` را اجرا کنید |
| جایگاه جدید در فیلتر دیده نمی‌شود | مسیر در manifest ثبت نشده | آیتم مسیر را به `manifest.json` اضافه کنید |
| فصل جدید دیده نمی‌شود | `roles` یا `level` نادرست است | شناسهٔ نقش و سطح فصل را بررسی کنید |
| ویدیوی فصل دیده نمی‌شود | `chapterId` با `chapter.id` یکسان نیست | دو شناسه را دقیقاً یکسان کنید |
| منبع نمایش داده نمی‌شود | URL بیرونی نیست | آدرس کامل `https://...` وارد کنید |
| تغییر تازه دیده نمی‌شود | صفحه Refresh نشده | صفحه را Refresh کنید؛ سرور `no-store` است |

## اجرای جایگزین با Python

اگر Node.js در دسترس نیست:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory "F:\Projects\airoadmap"
```

## استقرار خودکار روی IIS

هر Push روی شاخهٔ `main`، Workflow فایل `.github/workflows/deploy-iis.yml` را اجرا می‌کند:

1. تمام Roadmapها با `validate-roadmaps.js` بررسی می‌شوند.
2. فقط فایل‌های لازم برای نسخهٔ عملیاتی بسته‌بندی می‌شوند.
3. بسته روی Runner ویندوزی سرور دانلود می‌شود.
4. محتوای `D:\Sites\Skyboard\AiRoadmap` با نسخهٔ جدید همگام می‌شود.

استقرار فقط زمانی انجام می‌شود که اعتبارسنجی مرحلهٔ اول موفق باشد. اجرای هم‌زمان Deploymentها نیز غیرفعال است تا دو نسخه به‌صورت موازی روی IIS کپی نشوند.

### راه‌اندازی Runner روی سرور

در GitHub وارد مسیر زیر شوید:

```text
Repository → Settings → Actions → Runners → New self-hosted runner
```

سیستم‌عامل `Windows` و معماری `x64` را انتخاب کنید و Token کوتاه‌عمر نمایش‌داده‌شده را کپی کنید. سپس فایل `scripts/install-iis-runner.ps1` را روی سرور دانلود و PowerShell را با `Run as administrator` باز کنید:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\install-iis-runner.ps1
```

اسکریپت Token را به‌صورت مخفی می‌پرسد و تمام مراحل زیر را خودکار انجام می‌دهد:

- دریافت آخرین نسخهٔ Windows x64 Runner
- بررسی SHA-256 رسمی فایل دانلودی
- نصب در `C:\actions-runner`
- ثبت Label با نام `airoadmap-production`
- نصب Runner به‌صورت Windows Service
- اعطای دسترسی `Modify` روی `D:\Sites\Skyboard\AiRoadmap`
- شروع Service و نمایش وضعیت نهایی

> Token را فقط از صفحهٔ ساخت Runner بردارید و در فایل، Commit، Issue یا پیام عمومی قرار ندهید. این Token کوتاه‌عمر است.
